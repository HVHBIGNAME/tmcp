# Ключи и локальное управление

## Доступ MCP-клиента

Создайте ключ в **Доступ → Новый токен** или командой `tmcp token create`. Секрет показывается один раз; приложение хранит его SHA-256. По умолчанию разрешено только `files:read`.

Ключ передаётся в `Authorization: Bearer …` или вводится на странице подтверждения OAuth. OAuth проверяет PKCE, сессию браузера и зарегистрированный callback. Выданные OAuth-токены привязаны к ID и hash клиентского ключа и проверяют его текущие разрешения.

- Пауза или истечение ключа блокирует его и связанные OAuth-подключения, включая refresh.
- Замена ключа делает прежний секрет и связанные с ним grants недействительными; клиент подтверждает OAuth новым ключом.
- Удаление ключа отзывает доступ. Настройки остальных интеграций сохраняются.
- Команды и gateway работают с правами пользователя ОС; это не sandbox.

## Управление компьютером

Windows GUI и `tmcp` CLI управляют сервером через IPC, защищённый учётной записью ОС:

- **Windows:** named pipe доступен владельцу и SYSTEM; сетевым входам отказано. До установки ACL сервер не обрабатывает запросы и не публикует endpoint. WebView2 загружает локальные ресурсы и отправляет действия через native bridge; bridge проверяет origin, маршрут и метод, а pipe-клиент — владельца и PID сервера.
- **Linux/macOS:** Unix socket `0600` находится в отдельном каталоге `0700`. Клиент проверяет владельца и права socket и descriptor.

Панель, CLI и сервер запускаются от одного пользователя. Для удалённого управления сервером используйте SSH и `tmcp` на сервере. Браузерная страница и MCP-ключ не предоставляют доступ к локальным настройкам. Внешний HTTP listener обслуживает MCP/OAuth; control endpoints отсутствуют на нём.

## Обновление старой установки

Перед заменой файлов остановите старую версию через её GUI или `tmcp stop`. Установщик запускает `setup`, который удаляет устаревшие общие ключи и порт управления из `.env`, сохраняя остальные строки. При обновлении из исходников выполните `node dist/src/cli.js setup`.

Клиентские ключи из раздела «Доступ» сохраняются. OAuth-grants и коды с привязкой к этим ключам переживают миграцию. Grants старого общего ключа и grants без привязки удаляются; клиенту нужно снова подтвердить OAuth ключом из «Доступа». Повреждённые файлы credentials не сбрасываются автоматически.

Для проверок реального MCP передайте выпущенный приложением ключ через `TMCP_CHECK_KEY` в `npm run smoke`. Это входной параметр проверочного скрипта, а не дополнительный способ авторизации сервера.
