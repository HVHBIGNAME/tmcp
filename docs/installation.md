# Установка и обновление

## Windows

Скачайте единственный файл `TMCP.exe` из [релиза](https://github.com/HVHBIGNAME/tmcp/releases/latest) и запустите. Нужна Windows x64. Первый запуск распаковывает встроенные Node.js, .NET, Fixed WebView2 и cloudflared; отдельные установщики компонентов и права администратора не нужны. Интернет нужен для туннеля и внешних интеграций, но не для распаковки.

По умолчанию настройки находятся в `%LOCALAPPDATA%\TMCP\.env`, данные — в `.mcp-tunnel` рядом, компоненты версии — в `app/<hash>`. При включении автозагрузки EXE устанавливается как `%LOCALAPPDATA%\TMCP\TMCP.exe`. «Запускать свёрнутым в трей» — отдельный параметр в настройках и меню трея. Полный выход останавливает сервер, туннель и команды после подтверждения.

`TMCP.exe --home "D:\Apps\TMCP"` выбирает другой постоянный каталог; `--show` открывает окно независимо от настройки свёрнутого запуска. `--prepare-only` распаковывает компоненты без запуска сервера, `--headless` запускает сервер без GUI. В одном каталоге данных работает один экземпляр GUI.

Установщик `install.ps1` принимает:

| Параметр               | Значение по умолчанию                                 |
| ---------------------- | ----------------------------------------------------- |
| `-Mode auto\|gui\|cli` | `auto`: GUI на desktop Windows, CLI на Windows Server |
| `-InstallDir PATH`     | `%LOCALAPPDATA%\TMCP`                                 |
| `-Root PATH`           | Домашняя папка пользователя                           |
| `-Version v2.0.1`      | Последний опубликованный релиз                        |
| `-NoStart`             | Не запускать сервер после установки                   |
| `-Autostart`           | Явно включить автозапуск                              |

```powershell
$install = [scriptblock]::Create((irm https://raw.githubusercontent.com/HVHBIGNAME/tmcp/main/install.ps1))
& $install -Mode cli -Root C:\work -NoStart
```

Установщик использует тот же автономный EXE и проверяет его SHA-256 по метаданным GitHub. Он добавляет CLI и, в GUI-режиме, ярлык меню «Пуск». Исходная developer-сборка `npm run build:ui` по умолчанию использует установленный .NET Desktop Runtime 8 и Evergreen WebView2; релиз собирается командой `npm run build:standalone` на Windows x64.

## Linux / macOS

Переменные окружения:

| Переменная         | Назначение                             |
| ------------------ | -------------------------------------- |
| `TMCP_HOME`        | Каталог приложения                     |
| `TMCP_ROOT`        | Рабочая папка MCP при первой установке |
| `TMCP_VERSION`     | Тег релиза, например `v2.0.1`          |
| `TMCP_NO_START=1`  | Установить без запуска                 |
| `TMCP_AUTOSTART=1` | Включить автозапуск явно               |

```sh
curl -fsSL https://raw.githubusercontent.com/HVHBIGNAME/tmcp/main/install.sh -o /tmp/tmcp-install.sh
TMCP_ROOT="$HOME/work" TMCP_NO_START=1 sh /tmp/tmcp-install.sh
```

`curl`, `tar` и утилита SHA-256 должны быть доступны. Установщик загружает исходники тега из GitHub, выполняет `npm ci`, сборку TypeScript и удаляет dev-зависимости. При необходимости загружает Node.js 24 LTS в каталог приложения. На Alpine используйте совместимый Node.js из пакетного менеджера заранее. GUI предусмотрен для Windows; Unix-установка выбирает CLI.

Версия cloudflared и SHA-256 для каждой платформы закреплены в `scripts/cloudflared-release.json`. Установка скачивает проверяемый бинарный файл напрямую из официального релиза Cloudflare и не требует запроса к GitHub API.

Если сеть ограничивает исходящие соединения, в `.env` можно выбрать `CLOUDFLARED_PROTOCOL=quic` (UDP), `http2` (TCP) или `auto`. На Windows по умолчанию используется HTTP/2, чтобы не ждать повторных попыток QUIC в сетях с нестабильным UDP; на Linux/macOS — `auto`. Оба транспорта Cloudflare используют порт 7844. Для серверов с недоступным IPv6 задайте `CLOUDFLARED_EDGE_IP_VERSION=4`. Параметры применяются после `tmcp restart`.

Для переносимой установки без изменения PATH используйте `-NoPathUpdate` на Windows или `TMCP_NO_PATH=1` на Unix. Обёртка останется в каталоге `bin` внутри установки.

### Панель Linux-сервера через SSH

Откройте терминальную панель от имени пользователя, который запустил TMCP:

```sh
ssh -t user@server '~/.local/bin/tmcp'
```

CLI обращается к локальному Unix socket, защищённому правами владельца. Дополнительный пароль TMCP не нужен. Для автоматизации можно выполнить `ssh user@server '~/.local/bin/tmcp status --json'`. Windows GUI использует локальный named pipe и проверяет владельца и PID сервера.

На Linux без `DISPLAY` и `WAYLAND_DISPLAY` новая установка отключает скриншоты; файловые инструменты и команды работают без графической сессии.

## Обновление

1. Завершите нужные команды, затем выполните `tmcp stop`.
2. На Windows завершите GUI через меню трея, чтобы освободить EXE.
3. Повторите установку в тот же каталог.

При переходе с запуска из репозитория укажите старый каталог через `TMCP.exe --home "C:\coding\mcp-tunnel"` после полного выхода из старого GUI. Это сохраняет `.env`, ключи и настройки на прежнем месте. Для переноса в другой каталог сначала остановите приложение и перенесите `.env`, `.mcp-tunnel` и собственный `mcp-servers.json`; проверьте относительные пути в `.env`. Новая пустая установка автоматически не забирает данные из других каталогов.

Архивы содержат только код приложения. Выпущенные клиентские ключи, правила и настройки Telegram/Cloudflare сохраняются. Шаг `setup` точечно удаляет устаревшие общие ключи и порт управления из `.env`; действующие OAuth-grants, привязанные к клиентским ключам, сохраняются. Старые grants без такой привязки требуют нового подтверждения ключом из «Доступа». При обновлении Quick Tunnel адрес изменится; named tunnel сохранит hostname.

## Удаление

```sh
tmcp autostart off
tmcp stop
```

Затем удалите каталог установки и команду-обёртку. Windows: при необходимости удалите `%LOCALAPPDATA%\TMCP\bin` из пользовательского PATH и ярлык из меню «Пуск». Unix: удалите `~/.local/bin/tmcp`. Сначала сохраните нужные локальные настройки и ключи.
