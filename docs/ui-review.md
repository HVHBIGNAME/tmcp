# Проверка интерфейса TMCP

## Дизайн-направление

Рабочая панель для управления доступом и наблюдения за MCP-запросами. Главный визуальный элемент — путь реального запроса от клиента через ключ к инструменту и обратно. Адрес подключения, разрешения и результат операции должны читаться быстрее декоративных деталей.

- **Палитра:** графитовый фон, отдельная поверхность панелей, светлый основной текст, контрастные вторичные подписи, янтарный акцент действий и голубой обратный канал. Светлая тема использует отдельные, проверенные по контрасту значения цветов.
- **Типографика:** системный Segoe UI для русского текста; Cascadia/Consolas для команд, адресов и числовых данных. Основной текст и элементы управления крупнее технических метаданных. Подписи не превращаются в декоративный микротекст.
- **Компоновка:** слева навигация, справа выровненные адрес, краткое состояние и поток запросов. На узком экране приоритет получает содержимое, а формы и действия остаются доступными.
- **Состояния:** регистрация туннеля, проверка внешнего адреса и работа локального сервера — разные факты. Ошибки содержат конкретный результат и следующий шаг.
- **Движение:** только при реальных событиях или действиях пользователя; учитывается предпочтение уменьшенного движения.

## Источники

- [Anthropic: frontend-design](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md) — намеренная визуальная иерархия, сдержанность, проверка скриншотами.
- [WCAG 2.2: минимальный контраст](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) — минимум 4,5:1 для обычного текста и 3:1 для крупного.
- [WAI-ARIA: модальные диалоги](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) — управление клавиатурой, начальный фокус и возврат фокуса.

## Воспроизводимая проверка

`npm run test:a11y -- --screenshots` запускает отдельный тестовый сервер и проверяет страницы, диалоги, узкий экран и страницы OAuth. Отчёт axe, снимки дерева доступности и изображения сохраняются в `.mcp-tunnel/ui-audit/`. Проверка добавлена в browser job CI.

## Результат проверки 09.10.2026

- Все 26 сценариев axe прошли без автоматически выявленных нарушений. Оставшиеся задания для ручной проверки касаются определения фона у системных select и модальных диалогов: дополнительно проверены вычисленные цвета и скриншоты. Расчётные контрасты проходят соответствующие пороги.
- Прошли 13 браузерных сценариев: формы, ошибки, клавиатурный фокус, заморозка полей при сохранении, показ состояния, восстановление связи и текстовый вывод потенциально опасных имён интеграций.
- Новые ключи по умолчанию получают только `files:read`. Запись, команды, экран и gateway выбираются явно. Разрешения существующих ключей при этом не переопределяются.
- Панель использует native bridge и защищённый IPC. Из интерфейса удалены вход по отдельному ключу управления и настройки общего ключа.
- Проверки MCP/OAuth/IPC на Windows: 71 успешный тест, один POSIX-only тест пропущен. Проверены миграция привязанных grants, отказ старым ключам и отказ ограниченному Windows token в чтении/записи named pipe.
- Раздел «Автозагрузка и трей» проверен на собранном автономном EXE: постоянная установка `TMCP.exe`, включение и отключение регистрации автозапуска, сохранение ключей после удаления исходной загрузки, запуск свёрнутым без окна, возврат окна при повторном запуске, переход в «Доступ и ключи» из меню трея, отмена подтверждения выхода и полный останов с кодом 0.
- Размеры и число браузерных сценариев не изменились; новые снимки не создавались.

## Границы проверки

Указанные результаты относятся к локальному интерфейсу и изолированным тестам. Проверка настоящего OAuth через рабочий домен остаётся отдельной задачей. Регистрация туннеля не считается доказательством доступности его внешнего адреса: проверка внешнего адреса может завершиться ошибкой независимо от состояния приложения.

`files:read` разрешает читать содержимое выбранных рабочих папок, включая конфиденциальные файлы вне списка защищённых путей TMCP. Команды и gateway выполняются с правами пользователя ОС и не являются песочницей. Отдельный независимый аудит безопасности не проводился; замечания анализатора к размеру ряда функций остаются.

Замечания Aislop о `console.log` в CLI и установщике относятся к штатному выводу команд, а сообщения о hardcoded IDs — к стандартным именам OAuth-полей. Этот вывод и протокольные имена сохранены; правила анализатора не отключались. Unix-ветка нового IPC требует отдельного запуска на Linux/macOS; здесь проверена Windows-ветка.

Автоматический аудит дополняется проверкой читаемости, обрезания содержимого, клавиатуры и состояний ошибок. Отсутствие найденных нарушений не является сертификатом полной доступности или безопасности.
